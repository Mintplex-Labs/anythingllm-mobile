# Translations

The app UI is translated with [i18next](https://www.i18next.com/) + [react-i18next](https://react.i18next.com/).
All strings live in one JSON dictionary per language:

```
src/locales/
  languages.json      every language we ship (code, native name, English name)
  en/common.json      the ground truth - every key must exist here
  <code>/common.json  one per language, same keys as English; null = not translated yet
  resources.ts        GENERATED by `yarn translations:normalize` - do not edit
src/i18n/index.ts     setup, device language detection, setLanguage()
scripts/translations/ the yarn translations:* tooling
```

## Language on boot

1. On first launch the language comes from the device (Android per-app language or system language, iOS preferred
   languages). `pt-PT` falls back to `pt-BR`, `zh-Hant`/`zh-HK` to `zh-TW`, anything unsupported to English.
2. Once the user picks a language in **Settings > Language** it is saved and used from then on.
3. Any key that is `null`, empty or missing in a language shows the English string.

Right-to-left languages (Arabic, Hebrew, Farsi) are not supported yet - the layouts are not mirrored.

## Scripts

| Command | What it does |
| --- | --- |
| `yarn translations:normalize` | Creates missing language files, adds new English keys as `null`, drops removed keys, expands plural keys to each language's plural forms, regenerates `resources.ts`. |
| `yarn translations:create` | Translates every `null` entry in every language with a local Ollama model. Pass one language with `node scripts/translations/translate.mjs de`. |
| `yarn translations:verify` | CI check: keys used in code exist in English, every language has exactly the English keys, placeholders/tags are intact. |
| `yarn translations:unused` / `yarn translations:prune` | Lists (or deletes) English keys nothing in `src/` references. |

`translations:create` needs [Ollama](https://ollama.com) running with the translation model pulled:

```sh
ollama pull translategemma:4b
yarn translations:normalize && yarn translations:create
```

`OLLAMA_HOST` and `TRANSLATE_MODEL` override the defaults (`http://127.0.0.1:11434`, `translategemma:4b`).
`{{placeholders}}`, `<tags>` and the brand words in `scripts/translations/brandWords.json` are swapped for tokens
before a string reaches the model, and a translation that loses any of them is not retried - it is left
`null` (English) rather than written broken. Add a word to `brandWords.json` when it must never be translated.

## Adding a language

1. Add it to `languages.json` (`code` is a BCP 47 tag such as `pt-BR`; `nativeName` is how speakers write it).
2. `yarn translations:normalize && node scripts/translations/translate.mjs <code>`
3. Review the output, then `yarn translations:verify`.

## Writing UI strings

```tsx
import { Trans, useTranslation } from "react-i18next";
import i18n, { tKey } from "@/i18n";

const { t } = useTranslation();
<Text>{t("common.save")}</Text>
<Text>{t("chat.thread_renamed", { name })}</Text>          // "Renamed to {{name}}"
```

- **Keys** are nested, `snake_case`, grouped by screen: `scheduled_jobs.editor.title`.
- **`common.*`** holds shared verbs and one-word labels (Save, Cancel, Delete, Retry...). Use it instead of adding
  another "Cancel" under your screen. Only add to it when a word means the same thing everywhere.
- **Never build keys dynamically** (`` t(`status.${x}`) ``) - the scripts only see literal keys. Map values to keys
  with a literal object of `tKey("...")` entries instead.
- **Outside components** (utils, stores, callbacks) use `i18n.t("key")` when the string is shown, never at module
  load. For module-level constants store the key with `tKey("key")` and call `t()` when rendering.
- **Variables**: `{{name}}` interpolation. Never glue translated fragments together - word order differs by language.
- **Plurals**: add `key_one` and `key_other` in English using `{{count}}` and call `t("key", { count })`.
  Normalize creates the right forms for each language (Russian gets `_one/_few/_many/_other`, Japanese only `_other`).
- **Styled words inside a sentence** use `<Trans>` with named tags, inside a `<Text>`:

  ```tsx
  // "Tap <bold>Save</bold> to keep {{count}} change" / "..._other": "... {{count}} changes"
  <Text className="text-white">
    <Trans i18nKey="editor.save_hint" count={count} components={{ bold: <Text className="font-bold" /> }} />
  </Text>
  ```

- **Do not translate** anything sent to a model (system prompts, tool definitions, prompt templates), log and
  console output, internal error messages, analytics events, storage keys, URLs, or model/provider names.
  The developer tools screen (`src/screens/Dev`) and release notes stay English.
